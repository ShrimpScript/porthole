0.26.0

The first public release

26 September 2026featurefixes
  • The source is on GitHub. The repository is public at github.com/ShrimpScript/porthole. Each release there carries porthole.apk, the daemon for Linux on amd64 and arm64, and SHA256SUMS.
  • Porthole updates from its GitHub releases. At most once a day, and when you tap Check now in Settings > Updates, the app asks GitHub for the latest release. A newer one shows a banner with Not now and Update. The APK downloads from GitHub over HTTPS, and Android installs it only if it is signed with the same key as the Porthole you have. A switch in Settings > Updates turns the check off; the privacy policy says exactly what the check sends.
  • Builds from your projects keep their banner. portholed publish on the computer still offers an Android build of a project you are working on to your phone, with Install, and lists it under Settings > Other apps on the computer. The command now needs the app name: portholed publish app-release.apk 1.4.0 shopping-list. Porthole's own builds on the computer are no longer offered; Porthole updates only from its releases, so every install runs the same signed APK.
  • The daemon without Go. On a computer without Go, ./tools/install.sh downloads the release's portholed for linux amd64 or arm64 and checks it against the release's SHA256SUMS before installing it. A mismatch stops the install. --prebuilt asks for the release binary even where Go is installed.
  • porthole starts Claude Code where the phone can reach it. Run it instead of claude in a project's folder: it starts Claude Code inside tmux, in a session named after the folder, or brings back the one already open there. Arguments go to claude. The installer adds the name.
  • Fix: Allow and Deny from the phone now reach Claude Code. The approval hook answered in a shape current Claude Code does not accept, so it asked at the desk as if the phone had never replied.
  • Fix: terminals stay on the right session and stay live. A terminal is now bound to the session it was opened for, reopens itself after the connection drops instead of freezing on its last frame, follows the window when it is resized at the desk, and draws the character runs and sequences tmux sends that it used to drop.
  • The terminal scrolls back and goes full screen. Drag with one finger to walk the window's history (tmux's own scrollback); a chip brings you back to live. A full-screen button hides the header and the system bars.
  • The failsafe is a plain shell that fits the phone. It is sized to the screen, has its own scrollback and full screen, and runs with PORTHOLE_FAILSAFE=1 set, so a shell profile that attaches to tmux on every SSH login can leave it alone.
  • Fix: Start and Resume from the phone work after the computer reboots, before anyone has opened tmux at the desk.
  • Fix: a local slash command such as /model or /effort, or a ! shell command, no longer leaves a session showing as working forever.
  • Fix: the working clock in the session list counts from the start of the turn again; it no longer restarts at every tool call.
  • The composer makes room while you type. Typing folds the photo and slash buttons into one +, so the field is wider. Quick replies go away once something is typed, and the field grows to five lines, then scrolls.
  • Licences. Settings > Licences lists the fonts and libraries in the app.
  • A new site and docs. The app and the computer are drawn as they look, and the docs now cover getting started, updates, builds from your projects and every portholed command.

Coming from 0.25.0: earlier versions do not check GitHub, so install this one from the release page. Releases after it arrive as the update banner. On the computer, in the folder you cloned, pull, run the installer again (with --prebuilt if Go is not installed) and restart the service:

$ git pull
$ ./tools/install.sh
$ systemctl --user restart portholed
0.25.0

Coming back to a session

21 September 2026feature
  • Since you left. A session that ran on while you were away opens on the line where you stopped reading, with how many turns it got through and how long you were gone. Everything below the line is new.
  • Mute one session. A loop that finishes a turn every four minutes can be silenced from its details sheet without being hidden: it still appears in the list and in Needs you. Settings says how many are muted and unmutes them all.
0.24.4

Being far from the computer

21 September 2026feature
  • The failsafe SSH shell is now in Settings as well as on the failure card, so the login can be tried before anything breaks.
  • Settings reports whether Android has the app in battery optimisation, which decides whether a connection survives in your pocket.
  • A drop of more than two minutes ends with a notification when the computer answers again.
  • portholed doctor checks node-key expiry for the computer and each paired phone, whether Tailscale SSH is on, whether the daemon survives a reboot with no one logged in, whether the machine has slept, and free disk.
0.24.1 – 0.24.3

Two crashes, one symptom

21 September 2026fixes
  • The launch animation could throw when Android reclaimed the splash icon early, closing the app as it opened. It is decoration and can no longer close anything.
  • One session resumed in two terminal panes was listed twice, which the list refuses. The daemon now returns one row per session, newest pane winning, and the app removes duplicates as well.
  • Crash reporting: the app keeps its last crash, says so in a notification, and hands it to the computer on the next connection.
0.24.0

More than one computer

14 September 2026feature
  • Pair a second computer from Settings. Sessions from both appear in one list, named by machine, with unreachable ones kept apart rather than hidden.
  • Notifications, the widget and the approval card all work across machines.

0.20.0

Questions by tap

14 September 2026feature
