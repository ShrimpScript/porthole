0.37.1

A long message with pictures is sent, not left at the desk

3 October 2026fixes
  • Fix: a long message with pictures could be left unsent in Claude Code's box at the desk. Claude Code attaches pictures named in a message one by one, and an Enter that arrives while it does is lost. The daemon pressed Enter at once, so the message sat in the box at the desk unsent, while the phone was told it had gone and let go of it. Now the daemon types the message as one paste, waits a moment longer for one with files, and watches for Claude Code to record it. If the message is still in the box, it presses Enter again (only then, so a stray Enter never answers anything else). If Claude Code still has not taken it, the phone is told, and the message and its files come back to the box. Checked against a real Claude Code with three pictures. Mac and Linux alike.
0.37.0

Steady through a bad connection

3 October 2026featurefixes
  • A dropped connection no longer takes the screen with it. Until now a drop of a few seconds replaced the session with the failure card, threw away what you were typing, and on the way back reloaded the feed from scratch, so it flashed blank and jumped to the bottom. Now the feed, where you had scrolled to, an open sheet and the message you are typing all stay. A bar says Reconnecting… after a second or two, and after a few tries offers Options, the failure card's tools. When the computer answers, what happened meanwhile is added below what you were reading. The session list stays too, its rows reading "as last seen". The full failure card is kept for a computer that refuses the phone, or when there is nothing to show.
  • The message box keeps taking typing. It used to lock the moment the connection dropped, closing the keyboard mid-word. Now only Send waits for the computer.
  • Drafts are kept. Each session's unsent message is saved on the phone as you type. A drop, the app closing or the phone restarting no longer loses it.
  • A message stays in the box until it is typed. The box holds it, greyed, until the computer says it typed it into the session, which is a moment on a good connection. If it is refused, the reason shows and the text stays to send again. If the connection goes before the answer, the feed decides when it comes back: shown there means it was typed, missing means it stays in the box. Nothing is re-sent on its own. Text-only messages used to vanish when a send failed.
  • Sessions open at once, even offline. The phone keeps the last 200 rows of the 20 sessions you opened most recently, and the session list, in its private storage. A session opens from its copy straight away and catches up when the computer answers. With no connection, the copy is there to read, and the bar says when it was saved. Forgetting a computer deletes its copies. The privacy page lists exactly what is kept.
  • Mac and Linux alike. The daemon now answers every message the phone names, not only those with files.
0.36.0

Commands as cards

3 October 2026featurefixes
  • A slash command shows what it did. A command run in the session, at the desk or from the phone, was one grey line saying you ran it. It is now a card. /effort shows the level on a five-step meter, the CLI's description of it, and whether it is now the default for new sessions. /model shows the model by name, /rename the new name. /context shows the window to scale, the share held back for autocompact, and what fills it, largest first, with deferred tools named apart because they are not loaded yet. Any other command shows the CLI's reply, in red when it came as an error; a skill Claude Code loads by itself is a quiet line, not a card. A compaction and a /clear are lines across the feed, and a compaction says how many tokens it freed. Mac and Linux alike.
  • Session details answers /model, /effort, /cost, /stats and /status. Typed on their own, or picked from the slash menu, they open the sheet with its switches and numbers instead of a menu on the computer's screen. With an argument, such as /effort high, they are typed into the session as before. /context no longer switches to the terminal: its answer lands in the feed, and in a new By category section of the sheet, which can measure again. The effort switch gains max.
  • Fix: text Claude Code writes for itself showed as your messages. A skill's instructions, the summary a compaction leaves, and the /context table appeared as if you had sent them. They are no longer in the feed.
  • Fix: /compact showed as a message. It is now the command's card while the CLI compacts, with the working strip running, then the line that says how much it freed.
  • Fix: a message typed while Claude was busy could show twice. It showed as queued, and when Claude Code took it, it appeared again below while the queued bubble stayed until the session was reopened. The delivered message, or the command's card, now takes the bubble's place.
0.35.0

See the agents Claude starts

2 October 2026featurefixes
  • Subagents, live. When Claude hands work to an agent, the feed shows a card for it: what it was asked to do, what kind of agent it is and on which model, and, read from the agent's own transcript on the computer, how many tools it has used, what it is doing now and for how long. When an agent finishes, fails or is stopped, its card says so. The working strip counts the agents at work. Background agents that keep going after Claude's turn has ended get a strip of their own. Tap either for a sheet of every agent in the session, with each agent's own agents under it. The sessions list shows how many agents each session has at work. Mac and Linux alike.
  • Fix: delegated work had no name. Claude Code now calls its subagent tool Agent rather than Task, and the feed only knew the old name, so those rows showed no description.
0.34.0

A screw for a spinner

28 September 2026feature
  • The working icon is a turning screw. While Claude works, a small three-bladed screw, the ship's propeller, turns beside it. It is drawn in three dimensions: a blade brightens as it turns to face you and dims as it goes edge-on, with a faint trail behind each one. When a turn ends, the screw stands still beside "Worked for…". It replaces the copy of Claude Code's star spinner, in the list, the working strip, the feed and the composer. With animations off, it stays still.
0.33.0

Needs you, for permissions too

28 September 2026featurefixes
  • A session stopped on a permission prompt is under Needs you. Until now only a question put a session there. Now so does anything Claude Code itself reports it is stopped on you for: a permission prompt, a tool asking for input, a sandboxed command asking for the network. The row moves to the top with the amber ring and says what it wants ("waiting for you: Bash: git push --force origin main"). It stays there for as long as it waits, including after the approval card on the phone has timed out and gone back to the desk. A menu left open at the desk, such as /model, does not count. Mac and Linux alike.
  • Fix: a long command ran off the approval card. The command sat on one line that scrolled sideways, so its end, usually the part that matters, was out of view. It now wraps, so all of it is on the card.
0.32.0

Send a file from the phone

27 September 2026featurefixes
  • Attach any file, not only photos. The paperclip beside the message box offers a photo or a file: a PDF, a log, a spreadsheet, a zip, from the phone or anywhere the system's file picker reaches, up to 10 MB in all per message. The computer saves it in ~/.config/porthole/uploads, never in the project, under its own name, and the message tells Claude where it is. Files go in pieces, so a large one on a slow connection still arrives whole, and a message whose files did not go comes back to the message box. The computer keeps what the phone sent for two weeks. Mac and Linux alike.
  • Fix: a photo sent from the phone dropped the connection. The daemon accepted messages of at most 32 KB, and a photo is ten times that, so the phone was disconnected and the photo never arrived. It now takes them, and a message that cannot be sent says so instead of vanishing.
  • Rename a session. In a session's details, the pencil beside its name renames it with Claude Code's own /rename, so the new name is the one at the desk and in claude --resume too. A name given with /rename, at the desk or from the phone, now always comes before the titles Claude Code makes up.
0.31.0

Name a file with @

27 September 2026featurefixes
  • @ in the message box lists the session's files. Type @ and the files in the session's folder appear above the box, the most recently changed first; keep typing to narrow them by name or by a piece of the path. A tap puts the path in the message, and Claude Code reads that file along with it, as it does when you type @ at the desk. In a git repository the list is git's own: tracked files, and new ones that are not ignored. Elsewhere it is the folder's files a few levels down, leaving out hidden ones. Only the names reach the phone. Mac and Linux alike.
  • Fix: typing after a picked command went into its name. Pick /model from the list and type its argument, and the letters landed in the middle of the command (/moxdel). A command or file picked from a list now leaves the cursor at the end of the message.

Trusting a folder from the phone

27 September 2026feature
  • Trust a new folder from the phone. The first time Claude Code runs in a folder, it asks whether you trust it, before the session shows up anywhere. A New session started from the phone now brings that question to the phone: Trust this folder opens the session; Cancel quits Claude Code and removes the tmux session made for it. A Mac or a Linux computer, from the first screen

27 September 2026featurefixes
  • Set up a Mac or a Linux computer. What you'll need now asks which computer runs Claude Code, and Set up the computer shows that computer's steps only, with a switch between the two: the Tailscale app and Remote Login, Homebrew and portholed setup on a Mac; Tailscale SSH, the installer and linger on Linux. A new session from the phone

26 September 2026featurefixes
  • New session. The + at the top of the session list lists every folder Claude Code has been used in on your computers, most recent first, with a field for any other folder. Pick one and Claude Code starts there in a tmux session of its own, named after the folder, and opens on the phone as soon as it is up. A second one in the same folder gets its own session. 0.27.0

Porthole on a Mac

26 September 2026feature
  • The daemon runs on macOS. macOS 13 or later, Apple silicon or Intel, with the Tailscale app from the App Store or Tailscale's website. It runs as a launchd agent that starts when you log in and restarts if it fails, finds Tailscale however it was installed, and sees your sessions, tmux and dev servers the way it does on Linux.
  • Homebrew. brew install shrimpscript/tap/porthole, then portholed setup, which starts the background service and adds the approval hook in one step. It works on Linux too. Upgrades keep the service pointing at the current version.
  • The failsafe on a Mac signs in with the phone's own key. The Tailscale app on a Mac has no SSH server, so the failsafe goes through Remote Login instead. In Settings > If Porthole cannot connect, Add this phone's key makes an Ed25519 key on the phone, kept encrypted under a key in Android's Keystore, and the daemon adds it to ~/.ssh/authorized_keys, usable only from the phone's tailnet addresses and with no forwarding. Remove this phone's key and portholed revoke take it out. The same works on Linux computers that use their own sshd.
  • Restart over SSH knows the computer. The failsafe's restart uses launchd on a Mac and systemd on Linux, from any login shell, and starts the daemon on its own if the service manager refuses.
  • Screenshots and clips of a Mac's screen, with the system's own screencapture. macOS asks once, at the Mac, to allow it.
  • A Mac stays awake while it is needed. While a session is working or a phone is connected, portholed keeps the Mac from sleeping, on the power adapter only, and lets it sleep again after.
  • portholed doctor checks a Mac's own settings: whether it logs in by itself after a reboot, its sleep setting, Remote Login, and how many phone keys the failsafe has. Every check it runs now has a time limit.
  • New commands: portholed setup, portholed service install|restart|status|uninstall and portholed version.

Updating a Linux computer: run the installer again, so the service may write ~/.ssh for the failsafe key, then restart it:

$ git pull
$ ./tools/install.sh
$ portholed service restart
0.26.0

The first public release

26 September 2026featurefixes
  • The source is on GitHub. The repository is public at github.com/ShrimpScript/porthole. Each release there carries porthole.apk, the daemon for Linux on amd64 and arm64, and SHA256SUMS. From 0.27.0 they carry the daemon for macOS as well.
  • Porthole updates from its GitHub releases. At most once a day, and when you tap Check now in Settings > Updates, the app asks GitHub for the latest release. A newer one shows a banner with Not now and Update. The APK downloads from GitHub over HTTPS, and Android installs it only if it is signed with the same key as the Porthole you have. A switch in Settings > Updates turns the check off; the privacy policy says exactly what the check sends.
  • Builds from your projects keep their banner. portholed publish on the computer still offers an Android build of a project you are working on to your phone, with Install, and lists it under Settings > Other apps on the computer. The command now needs the app name: portholed publish app-release.apk 1.4.0 shopping-list. Porthole's own builds on the computer are no longer offered; Porthole updates only from its releases, so every install runs the same signed APK.
  • The daemon without Go. On a computer without Go, ./tools/install.sh downloads the release's portholed for linux amd64 or arm64 and checks it against the release's SHA256SUMS before installing it. A mismatch stops the install. --prebuilt asks for the release binary even where Go is installed.
  • porthole starts Claude Code where the phone can reach it. Run it instead of claude in a project's folder: it starts Claude Code inside tmux, in a session named after the folder, or brings back the one already open there. Arguments go to claude. The installer adds the name.
  • Fix: Allow and Deny from the phone now reach Claude Code. The approval hook answered in a shape current Claude Code does not accept, so it asked at the desk as if the phone had never replied.
  • Fix: terminals stay on the right session and stay live. A terminal is now bound to the session it was opened for, reopens itself after the connection drops instead of freezing on its last frame, follows the window when it is resized at the desk, and draws the character runs and sequences tmux sends that it used to drop.
  • The terminal scrolls back and goes full screen. Drag with one finger to walk the window's history (tmux's own scrollback); a chip brings you back to live. A full-screen button hides the header and the system bars.
  • The failsafe is a plain shell that fits the phone. It is sized to the screen, has its own scrollback and full screen, and runs with PORTHOLE_FAILSAFE=1 set, so a shell profile that attaches to tmux on every SSH login can leave it alone.
  • Fix: Start and Resume from the phone work after the computer reboots, before anyone has opened tmux at the desk.
  • Fix: a local slash command such as /model or /effort, or a ! shell command, no longer leaves a session showing as working forever.
  • Fix: the working clock in the session list counts from the start of the turn again; it no longer restarts at every tool call.
  • The composer makes room while you type. Typing folds the photo and slash buttons into one +, so the field is wider. Quick replies go away once something is typed, and the field grows to five lines, then scrolls.
  • Licences. Settings > Licences lists the fonts and libraries in the app.
  • A new site and docs. The app and the computer are drawn as they look, and the docs now cover getting started, updates, builds from your projects and every portholed command.

Coming from 0.25.0: earlier versions do not check GitHub, so install this one from the release page. Releases after it arrive as the update banner. On the computer, in the folder you cloned, pull, run the installer again (with --prebuilt if Go is not installed) and restart the service:

$ git pull
$ ./tools/install.sh
$ systemctl --user restart portholed

Coming back to a session

21 September 2026feature

Two crashes, one symptom

21 September 2026fixes
  • The launch animation could throw when Android reclaimed the splash icon early, closing the app as it opened. It is decoration and can no longer close anything.
